title: Reading and writing code
tags: programming, code, python, java, c, algorithm, data-structure, complexity, debugging, function, software
summary: For slides with code or algorithms: ask what the code does step by step, why it is written that way, its cost, and how it breaks.
---
Use when a slide shows code, pseudocode, an algorithm or a data structure.

Question moves:
- Trace it: "What does <snippet> output for <small input>, step by step?"
- Why this way: "Why does this use <construct> instead of <alternative>?"
- Cost: "What is the time / memory complexity of <algorithm>, and which line dominates it?"
- Edge cases: "What happens with an empty list / zero / a very large input here?"
- Errors: "What's the most common bug when writing <this>, and how would I spot it?"
- Shapes and types: "What are the types or tensor shapes at each step of <snippet>?"
- Connect: "How does <algorithm> compare with <algorithm> from the earlier lecture?"

Good: "Why is the inner loop in this insertion sort O(n) in the worst case but O(1) when the list is sorted?"
Weak: "Explain the code."
